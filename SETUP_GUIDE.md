# Amazon Connect AI Agent Demo — Setup Guide

This guide walks you through deploying a demo generated by the `connect-demo-generator` skill.
After running the skill, you'll have a folder (e.g., `insurance-demo/`) containing all the files
referenced below.

**Prerequisites:**
- AWS account with an Amazon Connect instance
- Deepgram API key stored in AWS Secrets Manager
- Access to Bedrock Agent Core, CloudFormation, IAM, and Lambda consoles

---

## Step 1: Deploy Lambda Functions (CloudFormation)

**File used:** `{vertical}_template.yaml`

1. Open **AWS CloudFormation** console
2. Click **Create stack** → **With new resources**
3. Select **Upload a template file** → choose `{vertical}_template.yaml`
4. Click **Next**
5. **Stack name:** something like `{Vertical}-Demo` (e.g., `Insurance-Demo`)
6. **AgentCoreGatewayRoleName:** Enter the name of your Agent Core Gateway service role
   - Find this in **IAM → Roles** — look for `AmazonBedrockAgentCoreGatewayDefaultServiceRole...`
   - Copy just the role **name** (not the full ARN)
7. Click **Next** → **Next** → check the IAM capabilities box → **Submit**
8. Wait for `CREATE_COMPLETE`
9. Go to the **Outputs** tab — you'll need the Lambda ARNs in Step 3

---

## Step 2: Create Bedrock Agent Core Gateway

1. Open **Bedrock Agent Core** console (search "Agent Core" in AWS console)
2. Click **Gateways** → **Create gateway**
3. **Name:** `gateway-{vertical}-demo` (e.g., `gateway-insurance-demo`)
4. **JWT scheme:** Select **Use existing**
5. **Discovery URL:** Paste your Connect instance access URL + `/.well-known/openid-configuration`
   - Example: `https://your-instance.my.connect.aws/.well-known/openid-configuration`
6. **Allowed audiences:** Enter `placeholder` for now (you'll update this after creation)
7. **Allowed clients:** Uncheck this
8. **Target:** Select **Integrations** → pick any provider temporarily (e.g., CloudWatch)
9. Click **Create gateway**
10. **Copy the Gateway ID** from the top of the page
11. Click **Edit** → replace `placeholder` in Allowed audiences with the Gateway ID → **Save**

---

## Step 3: Add Lambda Targets to Gateway

**Files used:** `{tool-name}_schema.json` (one per tool)

For each tool/Lambda:

1. In the gateway, scroll to **Targets** → click **Add**
2. Select **Lambda**
3. **Lambda ARN:** Paste the ARN from CloudFormation Outputs (Step 1) — keep the `:$LATEST` suffix
4. **Target name:** Use the tool name with hyphens (e.g., `account-lookup`)
5. **Target description:** Brief description of what the tool does
6. **Tool schema:** Open the corresponding `{tool-name}_schema.json` file, copy the entire contents, and paste into the schema editor
7. Click **Add target**

**If you get "Gateway service is not authorized to perform AssumeRole":**
- Go to **IAM → Roles** → find the gateway service role
- Edit the **Trust relationships** tab
- Add a statement allowing `bedrock-agentcore.amazonaws.com` to assume the role, with an `ArnLike` condition matching your gateway:
```json
{
    "Sid": "AllowNewGateway",
    "Effect": "Allow",
    "Principal": {
        "Service": "bedrock-agentcore.amazonaws.com"
    },
    "Action": "sts:AssumeRole",
    "Condition": {
        "StringEquals": {
            "aws:SourceAccount": "YOUR_ACCOUNT_ID"
        },
        "ArnLike": {
            "aws:SourceArn": "arn:aws:bedrock-agentcore:YOUR_REGION:YOUR_ACCOUNT_ID:gateway/gateway-{vertical}-*"
        }
    }
}
```
- Or use a wildcard to cover all gateways: `"aws:SourceArn": "arn:aws:bedrock-agentcore:YOUR_REGION:YOUR_ACCOUNT_ID:gateway/*"`

Repeat for each tool. Remove any placeholder targets (e.g., the CloudWatch one from Step 2).

---

## Step 4: Register MCP Server in Amazon Connect

1. Open **Amazon Connect** console → select your instance
2. Click **Third party applications** (left sidebar)
3. Click **Add application**
4. Select **MCP server** radio button
5. **Name:** `{Vertical} Demo MCP` (e.g., `Insurance Demo MCP`)
6. Select the gateway you created in Step 2
7. Select your Connect instance
8. Click **Add**

---

## Step 5: Create the AI Agent

1. In Amazon Connect, click the **star icon** (second from top in left sidebar) → **AI agents**
2. Click **Create AI agent**
3. **Name:** `{vertical}-demo-agent` (e.g., `insurance-demo-agent`)
4. **Type:** Orchestration (default)
5. **Copy from existing:** Select `Self-service orchestrator`
6. **Description:** `{Vertical} demo agent`
7. Click **Create**

### Add the Custom System Prompt

**File used:** `connect-system-prompt.yaml`

1. Go to **AI prompts** (left sidebar)
2. Click **Create AI prompt**
3. **Name:** `{vertical}-demo-prompt`
4. **Type:** Orchestration
5. **Copy from existing:** Self-service orchestration
6. Click **Create**
7. Replace the default prompt content with the contents of `connect-system-prompt.yaml`
8. Click **Publish**
9. Go back to your AI agent → **Edit**
10. Under **Prompts**, remove the default prompt and select your new one
11. **Save** and **Publish**

### Add Tools to the Agent

1. In the AI agent editor, scroll to **Tools**
2. Click **Add tool** → **Add existing tool**
3. Select the MCP server namespace from Step 4
4. Add each tool — rename them to be readable (e.g., `account-lookup` instead of the full gateway target name)
5. **Save** and **Publish**

### Set Security Profile

1. Scroll to **Security profiles** in the agent editor
2. Select **Admin** (or your preferred profile)
3. **Save** and **Publish**
4. Go to **Users** → **Security profiles** (left sidebar, people icon)
5. Click on the security profile (e.g., Admin)
6. Expand **Tools** section
7. Check all your new tools
8. **Save**

---

## Step 6: Create the Lex Bot

1. In Amazon Connect, go to **Conversational AI** (left sidebar)
2. Click **Create conversational AI bot**
3. **Name:** `{Vertical}-demo-bot`
4. Add the language you need. **Note:** Languages in Connect are locale-specific. Even though the model can handle en-US and en-GB, Connect treats them differently, so you'll need either a separate bot or an additional language added to your existing bot.
5. Check **Amazon Connect AI in connect intent**
6. Select your AI agent from the dropdown → **Confirm**
7. Configure your TTS/ASR providers (e.g., Deepgram)
8. Click **Build language**

---

## Step 7: Create or Import the Contact Flow

### Option A: Import the generated flow template

**File used:** `connect-flow-template.json`

1. Before importing, open the JSON file and replace the placeholder ARNs:
   - `REPLACE_WITH_ASSISTANT_ARN` → Your Wisdom assistant ARN
   - `REPLACE_WITH_AI_AGENT_VERSION_ARN` → Your AI agent version ARN (find in AI agent details)
   - `REPLACE_WITH_TTS_SECRET_ARN` → Your Secrets Manager ARN for TTS credentials
   - `REPLACE_WITH_LEX_BOT_ALIAS_ARN` → Your Lex bot alias ARN
2. In Amazon Connect, go to **Flows** (left sidebar)
3. Click **Create flow** → click the dropdown arrow → **Import flow**
4. Upload the modified JSON file
5. Verify all blocks are connected correctly
6. Click **Publish**

### Option B: Build the flow manually

1. Go to **Flows** → **Create flow**
2. Name it: `{Company} {Vertical} Demo Flow`
3. Add these blocks in order:
   - **Enable logging** → connects to:
   - **Set AI Agent** (select your agent) → connects to:
   - **Set voice** (configure TTS provider) → connects to:
   - **Get customer input** (Lex bot, with greeting text, enable AI agent) → connects to:
   - **End flow** (connect all error paths here too)
4. Click **Publish**

---

## Step 8: Assign a Phone Number

1. Go to **Phone numbers** (left sidebar, bottom)
2. Click **Claim a number** or select an existing one
3. Set the **Contact flow** to your new flow
4. **Save**

---

## Step 9: Test the Demo

1. **Warm-up call:** Call the number once before the real demo — this warms up the Lambda cold starts
2. **Primary test:** Call in as the primary demo customer (see `demo-guide.md` for the script)
3. **Verify:** Check that each tool call returns the expected data
4. **Troubleshooting:**
   - If tools fail: check Lambda logs in CloudWatch
   - If "insufficient permissions": verify the security profile includes your tools
   - If high latency: ensure Lambdas are warm (call once beforehand, or add provisioned concurrency)
   - If gateway errors: verify the trust policy on the gateway role includes your gateway ARN
